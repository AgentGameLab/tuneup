# 分段与任务书 — 大任务切开、各写一份、派出去、收回来验

> SKILL.md 主文件判定「command 调用 + 主车道 + 能切出两段以上」后加载本手册。小任务不加载。

---

## 1. 什么时候分段

三条都满足才分：

- command 调用且走主车道：用户要的是结果，不是一份指令稿
- 任务里有两段以上能**单独验收**的交付物（一个接口、一个页面、一份调研、一组素材）
- 至少有一段不挡主线：它在做的时候，主线有别的事可以做

不满足就不分，照旧自己做。分段有成本：每份任务书都要重新交代背景，结果回来还要再验一遍。一个文件能写完的东西切成三段，只会更慢。

**下一步马上要用的那段留在主线自己做**，派出去的是旁路：调研、素材、独立模块、能单独运行的验收脚本、审查。

---

## 2. 怎么切

按**交付物**切，不按工序切。「先设计、再实现、再测试」是工序，三段都交不出能单独验收的东西，实现完再补的测试也只是工序；「分数接口」「游戏页面」「玩法说明页」是交付物。

切完做三件事：

1. 标依赖：哪段要等哪段的结果。有依赖的顺序做，没依赖的并行。
2. 定接口：两段之间靠什么对接（字段名、文件路径、尺寸），写进双方的任务书，两边写的是同一句话。
3. 分文件：同一个文件同一时刻只归一段。两段都要改同一个业务文件，说明切错了，合成一段。入口、配置、清单这类共享文件归主线，各段把要加的内容写在回报里，由主线统一改。

---

## 3. 任务书模板

按“执行者只看得到这份任务书，看不到之前的对话”来写。每份都要能独立读懂。

```
【目标】这段要交出什么，一句话。它在整件事里起什么作用。

【交付物】文件放哪、叫什么；或者回报里要包含什么。

【已知】已经确定的事实、已经排除的做法、可以照着写的现成文件或模块。
        需要对方知道的内容直接贴进来，不写“见上文”“按之前说的”。

【边界】只动哪些文件或目录；不碰什么；不做什么（不提交、不部署、不联网……）。

【对接】和其他段的接口：字段、路径、格式。

【完成态】看得见、能当场判对错的条件，能用命令检查的给出命令。

【回报】按这个格式回：做了什么 · 产物在哪 · 完成态逐条的结果 · 没做或没验证的。
```

写的时候：

- **目标、交付物、边界、完成态四项不能缺。** 缺目标会跑偏，缺边界会越界改，缺完成态会停在“看起来完成”。
- 背景只给这段用得上的，不把整段对话倒给对方。
- 段是产物（代码、页面、场景）时，再按 `artifact-tasks.md` 补内容清单、覆盖契约和否定项。
- 段需要专业判断时，按 `domain-expert-lens.md` 把视角写进任务书。
- 任务书里不出现原任务没授权的动作。分段不扩大权限。

## 4. 各类段要多写的东西

| 段的类型 | 任务书里加什么 |
|---|---|
| **游戏** | 玩家每几秒在做什么（输入、核心循环、失败、得分、重来）；先交能玩的骨架，手感和表现单独一段；引擎和版本写明 |
| **界面 / 前端** | 这是给谁、在什么场合用的产品；颜色字号间距给具体值，不给形容词；每屏的状态（空、加载、正常、出错、超长）；哪些区域不许动 |
| **后端 / 接口** | 项目里照着哪个现成模块写；构建、类型检查、测试各用哪条命令；输入非法、超时、重复提交各怎么处理；不许靠改测试让测试通过 |
| **调研 / 核实** | 要回答的问题；每条结论带出处和原文短引；区分实测、官方说法、个人经验；查不到就写查不到 |
| **审查** | 给被审的东西本身，不给你的结论；只报真实缺陷，带位置和证据；默认只报不改，允许直接修的要在任务书里写明并限定文件 |

## 5. 派给谁

只派给宿主的分工规则或用户已经允许使用的执行者：子 agent、别的模型的命令行、别的会话。宿主自带的子 agent 算已允许；宿主规定了某类活归谁，照它的。拿不准某个执行者在不在允许范围内，或者派过去会产生没被允许的外部调用和费用，就不派。

能选时用不带对话历史的方式派；只能连历史一起带过去的通道，历史里有这段用不上、用户也没同意外传的内容时不用它。

没有可派的执行者：按段的顺序自己做。段多、对接多时任务书照写，它是你自己每一段的验收单；两三段的小活直接做，只把接口和完成态记下来。

并行时每个写文件的执行者用各自的工作目录。只读的可以共用。

---

## 6. 收回来怎么验

执行者的回报是报告，不是证明。

1. **先跑能跑的**：完成态里的命令、文件是否存在、能否打开。格式、数字、测试这类能机械判断的，不靠读回报判断。
2. **再看要判断的**：内容对不对、有没有漏项，对照任务书逐条看产物本身。
3. **查有没有绕路**：测试是不是被改了、有没有动边界外的文件。
4. **不过就带着具体问题退回**：哪一条没过、证据是什么。同一段最多退回两次，还不过就自己接手，或者报告卡在哪。
5. **合起来再验一次**：各段单独过了不等于拼起来能用，接口对接处最容易出问题。

执行者交回的结构化结果（表格、清单、代码）原样用，不重新改写一遍。

---

## 7. 长任务留记录

一轮做不完时，把这些写进一个记录文件（放临时或日志目录，不放进交付物），不留在对话里：做完的、在做的、卡住的、**没验证的**分开列；做过的决定和否掉的做法；下一步是什么。接手的人（或者压缩过上下文的你）靠这份文件继续，不靠回忆。记录里不写密钥、令牌和用不上的私密内容。

---

## 8. 交付

汇成一个结果交给用户：做成了什么、在哪、哪些段验过、哪些没验。不把任务书和各段的回报原样贴出来。

---

## 9. 不适用

- 一个人一口气能做完的任务
- 各段要改同一个业务文件
- 用户要的是指令稿：不分段，按主文件 Phase 3 的格式交付
- 用户说了在哪做、由谁做：照他说的
